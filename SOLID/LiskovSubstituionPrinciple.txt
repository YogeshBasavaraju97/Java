Liskov Substitution Principle (LSP)

Objects of a child class should be replaceable with objects of the parent class without breaking the program.

LSP = Child should behave like a proper Parent.

class Bird{
   public void fly() {
        System.out.println("Bird is flying");
}
}

class Sparrow extends Bird {

    @Override
    public void fly() {
        System.out.println("Sparrow is flying");
    }
}

This is fine because a sparrow can fly.
Bird bird = new Sparrow();
bird.fly();

The program works correctly.


But 

class Penguin extends Bird {

    @Override
    public void fly() {
        throw new UnsupportedOperationException(
            "Penguins cannot fly"
        );
    }
}

Now:
Bird bird = new Penguin();
bird.fly();

💥 The program crashes.
This means Penguin cannot properly substitute for Bird.
Therefore, this design violates Liskov Substitution Principle.

Instead, we should separate the abstractions.
class Bird {
    
    public void eat() {
        System.out.println("Bird is eating");
    }
}

Then:
interface FlyingBird {

    void fly();
}

Now Sparrow:
class Sparrow extends Bird implements FlyingBird {

    @Override
    public void fly() {
        System.out.println("Sparrow is flying");
    }
}

Penguin:
class Penguin extends Bird {

    // Penguin doesn't implement FlyingBird
}

Now our design makes sense:
              Bird
             /    \
            /      \
       Sparrow    Penguin
          |
          ↓
     FlyingBird

We can safely do:
Bird bird = new Penguin();
bird.eat();

No problem.
And:
FlyingBird bird = new Sparrow();
bird.fly();
